# План бесплатного запуска расписания

Проверено 6 октября 2026 года. Условия: 0 ₽, без привязки карты и автоплатежей; владелец редактирует расписание, второй человек только смотрит; оба пользователя находятся в России. ФИО и контакты в расписание не добавляем.

## Выбранная схема

- **Render Static Site** собирает и выдаёт сайт из приватного GitHub-репозитория. GitHub Pages на аккаунте GitHub Free не подходит: репозиторий сейчас приватный, а бесплатный Pages доступен для публичных репозиториев. Делать репозиторий публичным нельзя: в нём есть демо-расписание и ссылки, а история Git сохраняет старые версии.
- **Supabase Free** хранит аккаунты и расписание. RLS ограничивает чтение пользователями из `schedule_access`; запись разрешена только роли `editor`. Публичный signup выключен.
- Браузеру передаётся только publishable key. Secret/service-role key никогда не помещается в клиентский код или переменные `VITE_*`.

Render Static Site раздаёт готовые файлы через CDN, без отдельного запущенного web-service процесса. По документации Render статические сайты бесплатны, но используют общий лимит исходящего трафика и минут сборки. Если лимиты закончатся, сервис может приостановить сайт или новые сборки; без платёжного метода он не сможет автоматически списать деньги. Платные тарифы и дополнения не подключаем.

Supabase Free даёт 500 МБ базы и 5 ГБ исходящего трафика, но может приостановить проект после 7 дней низкой активности. Для двух человек лимитов хватит, однако бесплатная схема не гарантирует доступность в любой момент: приостановленную базу владелец возобновляет вручную в панели. У бесплатного плана нет автоматических резервных копий базы и SLA.

## Почему GitHub Pages заменён на Render

В настройках GitHub явно указано, что репозиторий приватный, а GitHub Pages предлагает обновить план или сделать репозиторий публичным. Согласно документации GitHub, Pages на GitHub Free доступен в публичных репозиториях. Публичность раскрыла бы не только код, но и текущую/прошлую историю репозитория. Поэтому Render Static Site раздаёт фронтенд из приватного репозитория.

## Состояние настройки

- Supabase-проект `Lesson schedule` существует на бесплатном плане, регион `eu-west-1`.
- Таблицы и RLS-политики уже существуют; права проверены: анонимный доступ отсутствует, редактор может записывать, читатель может только читать.
- Публичная регистрация выключена. Два аккаунта приложения созданы и добавлены в `schedule_access` с ролями `editor` и `viewer`; таблица `schedules` пока пуста.
- В GitHub Actions и Render заданы `VITE_SUPABASE_URL` и публичный `VITE_SUPABASE_ANON_KEY`. Secret/service-role key нигде в приложении не используется.
- Render Static Site подключён к приватному `Gogowski/Lesson-schedule`, ветке `main`, и публикует сайт по адресу [lesson-schedule-k5tj.onrender.com](https://lesson-schedule-k5tj.onrender.com/). Сборка закреплена на Node.js 24.21.0; автодеплой после ограничения GitHub App одним репозиторием проверен.
- Установка Render GitHub App ограничена только `Gogowski/Lesson-schedule`. Внутри этого репозитория приложению оставлены заявленные GitHub права: чтение кода и metadata, запись в Actions, статусы проверок, deployments, webhooks и связанные разделы. Расписание отдельно защищает Supabase Auth и RLS.
- Supabase Auth настроен на адрес сайта: Site URL и точный Redirect URL сохранены.
- GitHub Actions проверяет TypeScript и production-сборку. `render.yaml` хранит тот же рецепт сборки для повторяемой настройки.
- Production-сборка больше не включает локальные демо-уроки, имена и meeting URLs.

## Что осталось сделать

1. Войти на сайт обоими аккаунтами и проверить права. Пароли остаются у пользователей; вход под их учётными записями отдельно не проверен.
2. Войти редактором и создать пустое расписание либо сразу импортировать JSON. После создания занятия можно добавлять вручную, а позднее импортировать только новые записи или заменить всё расписание.
3. Убедиться, что читатель видит изменения, но не может редактировать; анонимный посетитель не читает данные.
4. Сверить сайт из российских сетей обоих пользователей. Сеть второго человека отдельно не проверена.
5. После запуска периодически экспортировать JSON-резервную копию из приложения и хранить вне репозитория.
