# Настройка расписания для реального использования

Для этого проекта выбрана связка **Render Static Site + Supabase Free**. Репозиторий GitHub остаётся приватным; Render нужен доступ только к нему для сборки сайта. Сайт публикует только клиентскую оболочку, а расписание остаётся в Supabase и читается после входа пользователями, которым назначена роль.

## Уже настроено

- Проект Supabase `Lesson schedule` находится на бесплатном плане.
- Таблицы `schedule_access` и `schedules` созданы, RLS включён.
- Политики дают чтение только пользователям из `schedule_access`, изменение — только роли `editor`; у `anon` нет прав.
- Публичная регистрация Supabase выключена.
- Таблицы пока пусты: аккаунтов нет, расписание не загружено.
- В GitHub Actions заданы публичные переменные сборки `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

## Завершить подключение бесплатного хостинга

1. Войдите или зарегистрируйтесь в Render. Не выбирайте платный план и не добавляйте платёжную карту.
2. При подключении GitHub выберите **только репозиторий `Gogowski/Lesson-schedule`**. Источник остаётся приватным; не включайте доступ ко всем репозиториям.
3. Создайте Blueprint из `render.yaml` в ветке `main`. Выберите бесплатный Static Site, если панель предлагает выбор тарифа. Параметры сборки уже описаны в файле: `npm ci && npm run build`, каталог `dist`.
4. При первом развёртывании укажите значение `VITE_SUPABASE_ANON_KEY` из **Project Settings → API Keys → Publishable key**. Это публичный ключ для браузера. Не используйте Secret key или старый `service_role`.
5. После успешной публикации запишите адрес `https://<имя-сайта>.onrender.com`.
6. В Supabase откройте **Authentication → URL Configuration** и задайте этот адрес в **Site URL** и в список **Redirect URLs**. Платные домены и дополнения не подключайте.

Render Static Site раздаёт статические файлы через CDN и не выключается как бесплатный серверный web service. Бесплатный план ограничивает общий трафик и минуты сборки. При отсутствии способа оплаты превышение лимита может остановить сайт или новые сборки до следующего периода; следите за использованием в панели Render.

## Добавить двух пользователей

Публичная регистрация закрыта. В Supabase откройте **Authentication → Users → Add user → Create new user** и создайте вручную два аккаунта: свой и читателя. Пароли задавайте сами в интерфейсе Supabase, не присылайте их в чат и не помещайте в GitHub.

Убедитесь, что новые пользователи подтверждены для входа. Не используйте email-приглашения Supabase по умолчанию для читателя: встроенная SMTP-служба в бесплатном режиме отправляет только на заранее разрешённые адреса команды Supabase и ограничена примерно двумя письмами в час. Для этих двух аккаунтов достаточно ручного создания и отдельных паролей. Восстановление пароля письмом сейчас не настроено.

После создания скопируйте UID пользователей и выполните в SQL Editor, подставив UUID:

```sql
insert into public.schedule_access (user_id, role)
values
  ('UID-ВЛАДЕЛЬЦА', 'editor'),
  ('UID-ЧИТАТЕЛЯ', 'viewer');
```

Не добавляйте людей в организацию Supabase ради входа в расписание: им нужен только аккаунт приложения, а не доступ к панели или базе.

## Финальная проверка и расписание

1. До загрузки настоящих данных проверьте вход владельца и читателя.
2. Убедитесь, что владелец видит редактирование, а читатель может только просматривать. Проверьте, что незалогиненный посетитель и аккаунт без строки в `schedule_access` не читают расписание.
3. Войдите владельцем и импортируйте JSON-резервную копию расписания. Не добавляйте ФИО и контакты, если они не нужны.
4. Откройте приложение со второго устройства и убедитесь, что обновление расписания появляется без повторной сборки сайта.
5. Периодически экспортируйте JSON из приложения и храните его вне GitHub. На Supabase Free автоматические резервные копии базы не включены.

**Ограничения бесплатного режима:** Supabase может поставить проект на паузу после семи дней низкой активности; несколько реальных запросов в день обычно помогают избежать паузы, но гарантии нет. После паузы владелец вручную возобновляет проект в панели. Поэтому связка стоит 0 ₽, но не даёт SLA и не гарантирует круглосуточную доступность.

## Ключи и данные

- Publishable/anon key предназначен для клиентского кода; защищают данные именно RLS и корректные политики.
- Secret/service-role key никогда не добавляйте в `VITE_*`, Render или клиентский код.
- Не добавляйте `.env`, настоящее расписание или его резервные копии в GitHub.
- Демо-расписание для локального сервера остаётся в репозитории, но production-сборка Supabase его не включает.
