# Настройка расписания для реального использования

Для этого проекта выбрана связка **Render Static Site + Supabase Free**. Репозиторий GitHub остаётся приватным, а установка Render GitHub App ограничена только `Gogowski/Lesson-schedule`. Внутри репозитория приложению доступны чтение кода и metadata, а также запись в Actions, статусы проверок, deployments, webhooks и связанные разделы. Сайт публикует только клиентскую оболочку, а расписание остаётся в Supabase и читается после входа пользователями, которым назначена роль.

## Уже настроено

- Проект Supabase `Lesson schedule` находится на бесплатном плане.
- Таблицы `schedule_access` и `schedules` созданы, RLS включён.
- Политики дают чтение только пользователям из `schedule_access`, изменение — только роли `editor`; у `anon` нет прав.
- Публичная регистрация Supabase выключена.
- Site URL и точный Redirect URL настроены на `https://lesson-schedule-k5tj.onrender.com/`.
- Два аккаунта приложения созданы и получили роли `editor` и `viewer`; таблица `schedules` пока пуста.
- В GitHub Actions заданы публичные переменные сборки `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
- Render Static Site подключён к приватному `Gogowski/Lesson-schedule`, ветка `main`; последний деплой успешно опубликован по адресу <https://lesson-schedule-k5tj.onrender.com/>.
- Переменные `VITE_SUPABASE_URL` и публичный `VITE_SUPABASE_ANON_KEY` добавлены также в Render. Секретный ключ Supabase не используется.

## Хостинг уже подключён

Production-сайт опубликован: <https://lesson-schedule-k5tj.onrender.com/>. Он собирается из ветки `main` командой `npm ci && npm run build`, каталог публикации — `./dist`. Render автоматически запускает сборку при изменениях в репозитории. Бесплатные лимиты остаются в силе; платные тарифы и дополнения не подключали.

Site URL и точный адрес в Redirect URLs уже внесены в Supabase **Authentication → URL Configuration**. Повторно настраивать эти пункты не нужно.

Render Static Site раздаёт статические файлы через CDN и не выключается как бесплатный серверный web service. Бесплатный план ограничивает общий трафик и минуты сборки. При отсутствии способа оплаты превышение лимита может остановить сайт или новые сборки до следующего периода; следите за использованием в панели Render.

## Аккаунты и пароли

Публичная регистрация закрыта. Два аккаунта приложения уже созданы и назначены редактору и читателю. При создании аккаунтов пароли задавайте сами в Supabase; не присылайте их в чат и не помещайте в GitHub. Supabase не показывает сохранённый пароль.

Если понадобится добавить пользователя, вручную создайте его в **Authentication → Users → Add user → Create new user**, затем добавьте его UID в `schedule_access`. Не добавляйте человека в организацию Supabase: для расписания ему нужен только аккаунт приложения.

Восстановление пароля для Supabase ещё не поддерживается интерфейсом приложения. В панели аккаунта доступна отправка письма восстановления, но прежде чем пользоваться ссылкой, нужно добавить в приложение экран задания нового пароля.

Для нового пользователя назначьте нужную роль записью в `schedule_access`:

```sql
insert into public.schedule_access (user_id, role)
values
  ('UID-ВЛАДЕЛЬЦА', 'editor'),
  ('UID-ЧИТАТЕЛЯ', 'viewer');
```

Не добавляйте людей в организацию Supabase ради входа в расписание: им нужен только аккаунт приложения, а не доступ к панели или базе.

## Финальная проверка и расписание

1. Аккаунты и роли уже заведены. Проверьте вход каждого человека; у каждого свой пароль.
2. После входа редактор может создать пустое расписание и добавлять занятия вручную либо сразу импортировать JSON.
3. После создания расписания JSON можно импортировать с добавлением только новых ID или заменить все записи (приложение спросит подтверждение). Не включайте ФИО и контакты, если они не нужны.
4. Откройте приложение со второго устройства и убедитесь, что читатель видит расписание, но не может его менять. Доступ из российской сети второго человека ещё отдельно не проверен.
5. Периодически экспортируйте JSON из приложения и храните его вне GitHub. На Supabase Free автоматические резервные копии базы не включены.

**Ограничения бесплатного режима:** Supabase может поставить проект на паузу после семи дней низкой активности; несколько реальных запросов в день обычно помогают избежать паузы, но гарантии нет. После паузы владелец вручную возобновляет проект в панели. Поэтому связка стоит 0 ₽, но не даёт SLA и не гарантирует круглосуточную доступность.

## Ключи и данные

- Publishable/anon key предназначен для клиентского кода; защищают данные именно RLS и корректные политики.
- Secret/service-role key никогда не добавляйте в `VITE_*`, Render или клиентский код.
- Не добавляйте `.env`, настоящее расписание или его резервные копии в GitHub.
- Демо-расписание для локального сервера остаётся в репозитории, но production-сборка Supabase его не включает.
