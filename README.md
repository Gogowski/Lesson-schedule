# Расписание занятий

## Запуск для разработки

Нужен Node.js 20.19+ (или 22.12+) и npm.

```powershell
npm ci
npm run dev
```

Откройте <http://localhost:3000>. Остановить сервер можно сочетанием `Ctrl+C`.

## Сборка и запуск production-версии

```powershell
npm run build
$env:NODE_ENV = 'production'
npm run start
```

Сервер слушает порт `3000`.

## Подготовка к реальному использованию

Текущая версия предназначена для локального демо, если облачная база не настроена. В production сборка без облачной конфигурации показывает экран настройки вместо демонстрационного расписания. План бесплатного размещения на Render Static Site и Supabase находится в [REAL_USE_PLAN.md](./REAL_USE_PLAN.md).

ФИО и контакты в расписание добавлять не нужно. Предлагаемый бесплатный вариант — Render Static Site для сайта и Supabase Free для входа и данных. Исходный код хранится в приватном репозитории; расписание хранится в закрытой таблице Supabase и не попадает в файлы сайта. Firebase Spark остаётся необязательным вариантом, но доступность бесплатной настройки не подтверждена.

Текущий локальный API нельзя публиковать как есть: он включён только в dev-режиме, PIN хранится открытым текстом, а production-сборка без настройки Supabase/Firebase показывает экран настройки. Перед реальным использованием настройте cloud-конфигурацию и правила доступа по инструкции ниже.

Для бесплатного размещения используйте инструкции в [supabase/SETUP.md](./supabase/SETUP.md): там описаны подключение Render к приватному репозиторию, создание двух аккаунтов и назначение ролей. Supabase-проект и политики уже настроены; публикация сайта, пользовательские аккаунты и загрузка расписания ещё не завершены. Текущая Firebase-конфигурация оставлена как необязательный старый вариант и для этого пути не нужна.

## Локальные демо-данные и PIN

Локальный dev-сервер использует `data/schedule.json` и начальный PIN `1234`; это только демо-режим. В реальном бесплатном размещении расписание хранится в закрытой таблице Supabase, а права проверяются Row Level Security. Не публикуйте `.env`, пароли или резервные копии расписания в GitHub.
